### Why this works

| Situation | Action taken | Reason |
|-----------|--------------|--------|
| `A[mid] == x` | Store `mid` in `result` and move `right` leftwards (`right = mid - 1`) | We want the *first* occurrence, so we keep looking left. |
| `A[mid] < x` | `left = mid + 1` | All elements up to `mid` are too small; the target must be to the right. |
| `A[mid] > x` | `right = mid - 1` | All elements from `mid` onward are too large; the target must be to the left. |

The loop terminates when `left > right`. At that point `result` either holds the left‑most index where `x` was seen, or stays `-1` if `x` never appeared.

## Things to keep in mind

1. **Sorted input** – Binary search only works if `A` is sorted in non‑decreasing order. If you have an unsorted list, you’ll need a linear scan (`O(n)`) or you must sort it first (`O(n log n)`).

2. **Duplicates** – The extra `right = mid - 1` after a match guarantees we keep looking leftward for earlier duplicates. If you only need *any* occurrence, you could return `mid` immediately.

3. **Pythonic tweaks** (optional)  
   * Use `bisect` from the standard library: `bisect_left(A, x)` gives you the insertion point, which is exactly the first index where `x` could appear. Then you just need to verify that `A[idx] == x`.
