## What’s wrong with the current code?

[code block omitted]

1. **`max_ending + n` instead of `max_ending * n`**  
   The product of a subarray ending at the current element must be either  
   * the element itself (`n`),  
   * the previous maximum product extended by the current element (`max_ending * n`), or  
   * the previous minimum product extended by the current element (`min_ending * n`).  
   Adding `n` (`max_ending + n`) is unrelated to the product problem and will produce completely wrong results.

2. **Simultaneous assignment without a temporary variable**  
   In Python the right‑hand side of a tuple assignment is evaluated **before** any of the left‑hand side targets are updated. That means the expression `min_ending * n` on the right side still uses the *old* `min_ending`, which is fine, but the expression `max_ending * n` also uses the *old* `max_ending`. The real issue is that after we compute the new `min_ending`, we need the *old* `max_ending` for the new `max_ending` (and vice‑versa). The current code works because of the tuple‑unpacking order, but it’s easy to get wrong and is less readable than the classic “store the old value in a temporary variable” approach.

3. **Missing edge‑case handling**  
   * Empty list (`arr == []`) will raise an `IndexError`.  
   * The algorithm works for zeros and negative numbers, but it’s worth explicitly testing those cases.

## Correct algorithm

The standard O(n) solution keeps two running values:

* `max_ending` – the maximum product of a subarray that **ends** at the current index.
* `min_ending` – the minimum product of a subarray that ends at the current index (needed because a negative number can turn a small minimum into a large maximum).

At each step we compute the three candidates (`n`, `max_ending * n`, `min_ending * n`) and update both `max_ending` and `min_ending`. The global answer `max_so_far` is the maximum of all `max_ending` values seen so far.

### Why this works

* **`n`** – start a new subarray at the current element.
* **`old_max * n`** – extend the previous *maximum* subarray; if `n` is positive this will keep the product growing.
* **`min_ending * n`** – extend the previous *minimum* subarray; if `n` is negative this can turn a large negative product into a large positive one.

Because we keep both the best and the worst product ending at each position, we never miss a candidate that could become the global optimum later.
