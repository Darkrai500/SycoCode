## 2. Typical “gotchas”

### a. Negative index may be surprising
In Python a negative index is interpreted as counting from the end of the list (`-1` → last element). If you later do something like `a[left_insertion(a, x)]` without checking the result, you’ll unintentionally fetch the last element when `x` is smaller than everything else.

**Fix:** Guard against the `-1` case, or return `None`/raise an exception instead.

### b. Empty list
`bisect_left([], x)` returns `0`, so the function returns `-1`. That’s consistent with the “no predecessor” rule, but you may want to handle the empty‑list case explicitly.

### c. List must be sorted
`bisect` assumes the sequence is sorted in non‑decreasing order. If you pass an unsorted list you’ll get a meaningless result. It’s a good idea to document that precondition (or assert it in debug builds).

### d. Duplicate values
When `x` equals an existing value, `bisect_left` points to the *first* occurrence. Subtracting 1 therefore gives you the element **before** that first occurrence. If you wanted the element *right before the specific occurrence* you’re interested in, you’d need a different approach (e.g., `bisect_right`).
